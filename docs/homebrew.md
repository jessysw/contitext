# Homebrew installation and upgrades

Homebrew is an additional package manager for the native Python deployment.
It uses the same PostgreSQL database, CLI, MCP tools and permissions as PyPI and
Docker. No Homebrew account is required. This is a project-maintained tap, not a
Homebrew/core formula.

## Install

```sh
brew install jessysw/tap/contitext
"$(brew --prefix)/opt/contitext/bin/contitext" --version
brew test contitext
```

Homebrew supplies an isolated Python 3.14 environment and builds checksummed,
pinned dependencies. The initial build can take several minutes. Do not install
extra Python packages into the formula's environment. PyPI remains available for
Python 3.11–3.14; Docker remains available for a combined app/database deployment.

Installation does not start a service, install a PostgreSQL server, create a
database, run migrations, generate credentials or change agent settings. The
formula's `libpq` dependency is a PostgreSQL client library, not a database server.
Supply PostgreSQL 16+ and use the [native initialization workflow](installation.md#option-1-python-package).
Keep configuration and credentials outside Homebrew's `Cellar` and `opt` trees.

If another `contitext` executable or operator wrapper already exists, inspect
`command -v contitext`. Homebrew does not replace wrappers outside its prefix.
Use the explicit stable path below to select this installation.

## Connect agents

After initialization, generate a stdio MCP entry with a stable absolute path:

```sh
"$(brew --prefix)/opt/contitext/bin/contitext" client-config \
  --config-file /absolute/private.env \
  --executable "$(brew --prefix)/opt/contitext/bin/contitext"
```

Use your real private configuration path. Merge the entry into your client's MCP
settings and install the [agent instructions](agent-installation.md). Homebrew
includes the optional adapter installer and protocol under
`$(brew --prefix)/opt/contitext/share/contitext`; run that installer explicitly
with the same options documented in the agent guide. It never runs on `brew install`.

The eight supported agent families use the same protocol and existing lifecycle
infrastructure. Homebrew does not add a chat interceptor or bypass host trust.
The [native-host limitations](acceptance-0.8.3.md) still apply.

Starting with 0.8.4, hooks/plugins generated from the currently linked Homebrew
installation use its verified `opt/contitext/libexec/bin/python` link. They can
follow future formula upgrades. Do not replace that link with a resolved,
versioned Cellar path. Existing profiles generated by a different installation
are not rewritten automatically: explicitly refresh those profiles when changing
installation method, preserving their connection, mapping and state paths, and
complete the client's normal trust review if requested.

## Upgrade and uninstall

```sh
brew update
brew upgrade contitext
"$(brew --prefix)/opt/contitext/bin/contitext" --version
brew test contitext
"$(brew --prefix)/opt/contitext/bin/contitext" --env-file /absolute/private.env doctor
```

The 0.8.4 update does not change the database schema. Follow the release's upgrade
notes and back up your data before any later migration. Restart long-lived
Contitext processes and reload MCP connections after a binary upgrade. Fresh
stdio processes use the new version; an already running process does not change.

```sh
brew uninstall contitext
```

Uninstall removes the package. It does not delete private configuration,
credentials, database data, exports or agent settings. Remove obsolete agent
entries explicitly if you are no longer using Contitext. Other packages and
PostgreSQL are not automatically removed by the formula.

## Release automation and verification

A stable PyPI release triggers a formula update PR in
[jessysw/homebrew-tap](https://github.com/jessysw/homebrew-tap). The generator resolves
macOS/Linux dependencies for Python 3.14, pins source URLs and SHA256 hashes, and
uses system `libpq` with the source-built Psycopg driver. The tap checks macOS
Apple Silicon, macOS Intel and Linux before merging automated formula updates.

The release job uses `HOMEBREW_TAP_TOKEN`: a fine-grained GitHub token owned by
`jessysw`, limited to **homebrew-tap**, with **Contents: read/write** and
**Pull requests: read/write**. Store it only as an Actions secret in the source
repository. The default repository-scoped `GITHUB_TOKEN` cannot push to the tap.
Rotate the token before expiry; no admin, workflows or organization permission
is needed. Dependency resolution runs before the token is supplied to the push
step. The tap's merge workflow never executes pull-request code with write access.

If a release update fails after PyPI publication, do not overwrite the published
package or tag. Fix the packaging problem and rerun **Update Homebrew tap** with
the existing stable version. A PR whose checks fail remains open for investigation.

CI uses disposable PostgreSQL and synthetic projects. It checks CLI startup,
real MCP initialization/write/read, all eight adapter command contracts, previous
formula upgrade when available, preservation of private files and context, and
uninstall. These are package/adapter tests; they do not claim interactive validation
inside all eight agent applications. Platform results must be reported separately
in the release acceptance record.
